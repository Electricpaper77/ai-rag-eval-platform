Architecture Flow

How It Works

The page maps directly to repo artifacts, so a reviewer can inspect the implementation instead of relying on screenshots alone.

  1. 01 Input prompts

    Controlled eval fixtures and API requests define expected behavior.

  2. 02 RAG answer generation

    Responses are produced or replayed with retrieved context expectations.

  3. 03 Citation validation

    Grounded answers must include the required source references.

  4. 04 Hallucination checks

    Unsupported claims and overconfident answers are flagged.

  5. 05 Refusal / safety checks

    Unsafe, PII, and prompt-injection cases must be blocked or refused.

  6. 06 JSONL logging

    Each case is persisted with metrics, risk category, and failure reasons.

  7. 07 Regression test suite

    Pytest protects the evaluator contract and artifact schema.

  8. 08 Metrics dashboard

    Summary cards expose pass rate, hallucinations, citations, refusals, and p95.

Controlled Benchmark Notice

Metrics are fixture results, not production benchmark claims.

The visible metrics come from deterministic controlled fixtures checked into the repo. They should not be represented as general production benchmark claims, vendor model comparisons, or live customer traffic results. Cost is mock-estimated and the proof run does not require a paid vendor model API.
