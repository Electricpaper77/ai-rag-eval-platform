# Gate 13 Cloud Run Deployment Readiness

Status: prepared only. No Cloud Run service, paid resource, public endpoint, or IAM binding has been created by this repository change.

## Verified Starting Point

- Gate 12 merged to `main` through PR #99.
- The FastAPI container starts on Linux and serves `/health`, `/metrics`, `/openapi.json`, `/evaluate`, and `/v1/chat/completions` in GitHub Actions.
- Docker runtime evidence is generated by the `AgentTrust Container Runtime Smoke` workflow.
- GPU benchmark records with `server_unavailable` or zero throughput are schema and availability evidence only. They are not evidence of real GPU hardware performance.

## Deployment Model

Recommended smallest secure deployment:

- Backend: Cloud Run service from the existing Dockerfile.
- Image registry: Artifact Registry in `us-central1`.
- Public hostname: use API Gateway, External HTTPS Load Balancer, or an approved custom domain in front of the Cloud Run service if internet access is required. Keep the Cloud Run service itself private by default.
- Authentication: Cloud Run IAM at the service boundary plus an application API key for protected application routes. The application API key is defense in depth, not a replacement for Cloud Run IAM, API Gateway, or load-balancer authentication.
- Frontend: configure the frontend or demo host to call the Cloud Run backend URL through an environment-provided API base URL. Do not hardcode `localhost`.

## Runtime Environment Variables

Required for the safe production profile:

- `PORT=8080`
- `INFERENCE_BACKEND=mock` unless a verified upstream inference backend is approved.
- `AGENTTRUST_REQUIRE_API_KEY=true`
- `AGENTTRUST_API_KEY` from Secret Manager, not plaintext environment configuration.
- `ARTIFACT_DIR=/tmp/agenttrust-artifacts` for ephemeral Cloud Run runtime artifacts.

Optional, only after separate review:

- `GEMINI_API_KEY` for Gemini-assisted evaluator behavior.
- `OPENAI_COMPAT_ENDPOINT`, `OPENAI_COMPAT_MODEL`, `OPENAI_API_KEY` for an OpenAI-compatible upstream.
- `VLLM_ENDPOINT` or `TRITON_ENDPOINT` for private model-serving backends.
- `OTEL_EXPORTER_OTLP_ENDPOINT` or `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` for a managed telemetry collector.
- `DEPLOYMENT_ENVIRONMENT=production`
- `OTEL_SERVICE_NAME=agenttrust-iq-api`

## Route Exposure Policy

Application-level public route:

- `GET /health`

Authenticated routes:

- `POST /evaluate`
- `POST /v1/chat/completions`
- `GET /metrics`
- `GET /openapi.json`, `/docs`, and `/redoc`
- `/dashboard/*`
- `/api/recruiter-*`
- `/api/gpu-lab/*`
- `/platform/*`
- `/eval/*`
- `/gpu/status`
- `/benchmark/*`
- Any route that reads artifacts, writes evaluation records, returns traces, or starts control-plane behavior.

The application enforces this with `AGENTTRUST_REQUIRE_API_KEY=true`. For Cloud Run deployments, send the application key separately from the Cloud Run IAM bearer token:

```bash
X-AgentTrust-API-Key: $AGENTTRUST_API_KEY
```

## Cloud Run Commands

Set variables:

```bash
export PROJECT_ID="your-gcp-project"
export REGION="us-central1"
export REPOSITORY="rag-eval-repo"
export SERVICE="agenttrust-iq-api"
export IMAGE_TAG="$(git rev-parse --short HEAD)"
export IMAGE="$REGION-docker.pkg.dev/$PROJECT_ID/$REPOSITORY/$SERVICE:$IMAGE_TAG"
```

Enable required APIs after billing/project approval:

```bash
gcloud services enable run.googleapis.com artifactregistry.googleapis.com cloudbuild.googleapis.com secretmanager.googleapis.com
```

Create Artifact Registry repository if it does not already exist:

```bash
gcloud artifacts repositories create "$REPOSITORY" \
  --repository-format=docker \
  --location="$REGION" \
  --description="AgentTrust IQ container images"
```

Create least-privilege runtime identity:

```bash
gcloud iam service-accounts create agenttrust-iq-api \
  --display-name="AgentTrust IQ Cloud Run runtime"
```

Create the API key secret:

```bash
openssl rand -base64 32 | \
  gcloud secrets create agenttrust-api-key --data-file=-
```

Grant only secret read access to the runtime identity:

```bash
gcloud secrets add-iam-policy-binding agenttrust-api-key \
  --member="serviceAccount:agenttrust-iq-api@$PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/secretmanager.secretAccessor"
```

Build and push the verified Docker architecture:

```bash
gcloud builds submit --tag "$IMAGE"
```

Deploy without anonymous IAM invoker access:

```bash
gcloud run deploy "$SERVICE" \
  --image "$IMAGE" \
  --region "$REGION" \
  --service-account "agenttrust-iq-api@$PROJECT_ID.iam.gserviceaccount.com" \
  --no-allow-unauthenticated \
  --set-env-vars "PORT=8080,INFERENCE_BACKEND=mock,AGENTTRUST_REQUIRE_API_KEY=true,ARTIFACT_DIR=/tmp/agenttrust-artifacts,DEPLOYMENT_ENVIRONMENT=production,OTEL_SERVICE_NAME=agenttrust-iq-api" \
  --set-secrets "AGENTTRUST_API_KEY=agenttrust-api-key:latest" \
  --cpu 1 \
  --memory 1Gi \
  --concurrency 10 \
  --timeout 120 \
  --min-instances 0 \
  --max-instances 2 \
  --no-cpu-boost
```

Do not grant `allUsers` the Cloud Run `roles/run.invoker` role without a separate security review. If a public demo URL is required, put API Gateway or an External HTTPS Load Balancer in front of Cloud Run and expose only the intended routes, such as `/health`, while forwarding protected routes with authentication. The application API key should remain enabled either way.

## Validation Commands

```bash
export BASE_URL="$(gcloud run services describe "$SERVICE" --region "$REGION" --format='value(status.url)')"
export CLOUD_RUN_IDENTITY_TOKEN="$(gcloud auth print-identity-token)"
export IDENTITY_TOKEN="$CLOUD_RUN_IDENTITY_TOKEN"
export AGENTTRUST_API_KEY="$(gcloud secrets versions access latest --secret=agenttrust-api-key)"
pwsh ./scripts/smoke_gate13_cloudrun.ps1 -BaseUrl "$BASE_URL" -ApiKey "$AGENTTRUST_API_KEY"
```

The smoke script sends the Cloud Run IAM identity token as `Authorization: Bearer ...` and sends the application key separately as `X-AgentTrust-API-Key`. It does not print either credential.

Manual equivalent checks:

```bash
curl -fsS -H "Authorization: Bearer $IDENTITY_TOKEN" "$BASE_URL/health"
curl -i "$BASE_URL/health"
curl -i -X OPTIONS "$BASE_URL/evaluate"
curl -i -H "Authorization: Bearer $IDENTITY_TOKEN" "$BASE_URL/metrics"
curl -i -H "Authorization: Bearer $IDENTITY_TOKEN" -H "X-AgentTrust-API-Key: invalid-api-key" "$BASE_URL/metrics"
curl -fsS -H "Authorization: Bearer $IDENTITY_TOKEN" -H "X-AgentTrust-API-Key: $AGENTTRUST_API_KEY" "$BASE_URL/metrics" | head
curl -fsS -H "Authorization: Bearer $IDENTITY_TOKEN" -H "X-AgentTrust-API-Key: $AGENTTRUST_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Summarize the deployment evidence.","model_response":"The service passed health checks. [1]","expected_behavior":"Answer with citation.","risk_category":"citation","retrieved_evidence":[{"source_id":"1","snippet":"The service passed health checks."}]}' \
  "$BASE_URL/evaluate"
```

Expected:

- `/health` returns HTTP 200 for a caller authorized by Cloud Run IAM. If an API Gateway or load balancer exposes `/health`, that public frontend returns HTTP 200 without the application API key.
- Unauthenticated direct Cloud Run requests return HTTP 403 at the Cloud Run IAM layer.
- `/metrics` returns HTTP 401 when the caller is authorized by Cloud Run IAM but omits or sends an invalid application API key.
- Authenticated `/metrics` returns Prometheus text.
- Authenticated `/evaluate` returns HTTP 200 and an evaluation result.
- Unauthenticated `OPTIONS` requests to direct Cloud Run return HTTP 403. IAM-authorized `OPTIONS` requests are allowed past application API-key middleware so the deployed CORS/routing policy can answer them.

## Rollback

List revisions:

```bash
gcloud run revisions list --service "$SERVICE" --region "$REGION"
```

Route all traffic to the previous known-good revision:

```bash
gcloud run services update-traffic "$SERVICE" \
  --region "$REGION" \
  --to-revisions "PREVIOUS_REVISION=100"
```

Disable public access immediately if authentication behavior is suspect:

```bash
gcloud run services remove-iam-policy-binding "$SERVICE" \
  --region "$REGION" \
  --member="allUsers" \
  --role="roles/run.invoker"
```

## Cost Controls

Cloud Run costs depend on region, CPU, memory, request volume, and outbound network. This readiness plan caps cost risk with:

- `min-instances=0`
- `max-instances=2`
- `cpu=1`
- `memory=1Gi`
- `concurrency=10`
- mock backend by default, so no external model spend

Billing must be enabled before deployment. Artifact Registry storage, Cloud Build minutes, Secret Manager access, logs, and Cloud Run CPU/memory/request charges may apply.

## Approval Required For Live Deployment

Before any public deployment, explicitly approve:

1. GCP project id and billing account.
2. Region.
3. Artifact Registry repository creation or reuse.
4. Secret Manager secret creation for `AGENTTRUST_API_KEY`.
5. Whether public access should be provided through API Gateway, External HTTPS Load Balancer, or kept fully private.
6. Optional custom domain, for example `api.agenttrust-iq.example.com`.
7. Any exception to private Cloud Run IAM, including `allUsers` invoker access.
